# Pawside 用户画像与内容信息屋（Message House）

**内部文档，不对外展示。** 不要放进 `public/`，不要出现在官网页面里。
状态：草稿 v0.1，2026-10-06。来源是产品负责人 Sylvan 对目标用户的口述，**全部是待验证的假设**，不是调研结论。目前内测只有 2 个用户，没有统计数据。凡标「假设」的，都需要用真实用户的话去验证。

这份文档的用途：写官网、App 内文案、AI 反馈 prompt、增长内容时，先回到这里问一句——**这句话，是这个人听得懂、会觉得「这跟我有关」的吗？**

---

## 0. 一条总原则

**用户不会因为我们有多严谨而选我们，而是因为他能想象自己在用它。**

所以所有对外文案按这个顺序写：

1. **价值**：对他的生活意味着什么（他在什么场景、省了什么麻烦、得到了什么）。
2. **画面**：他怎么用（具体到「站在器械前」「点完外卖」）。
3. **证据**：为什么可信（一句话，放在后面）。
4. **机制**：它内部怎么工作（几乎不讲；要讲也放 FAQ 的最底部）。

内部的工程原则（数字由程序算、模型只写文案、数字可追溯）是**我们自己要守的底线，不是卖点**。用户感受到的是「它说的数我对得上」，不是「它的架构」。

## 1. 目标人群（大人群）

**18–30 岁、想变得更健康、但没有资源走专业路线的人。**

共同点：
- 刚成年到三十岁左右：学生、实习生、初入职场。
- **时间是碎的**：上课、加班、通勤之间挤出来的 30–60 分钟。
- **没有预算，也没有固定时间请私教。**
- 愿意**从网上自学**健身和饮食知识，但学得很散。
- 有健身房，或者能徒手练；器械知识有限。
- 不是专业健身人士，**术语门槛是真实存在的**。

不是我们的人群（现阶段不服务，也不为他们写文案）：
- 专业健身者、备赛者：需要的是精细化的周期和重量管理。
- 有疾病、伤病、孕产、进食障碍的人：需要医生和专业人士，不是 App。
- 未满 16 岁的人（隐私政策已写明不面向）。

## 2. 用户画像（Persona）

> 下面是一个**合成人物**，用来帮写作的人「看见」读者。不是某个真实用户。名字、细节是虚构的，行为特征来自产品负责人的描述。

### 小周（合成）

- **24 岁**，工作一年多，下班晚，周末想练但常常不知道练什么。
- 办了健身房卡（或者在宿舍 / 家里用哑铃、弹力带），**去过，但每次都在凭感觉乱练**：胸练一练，背随便拉几下，然后觉得「好像也没练到什么」。
- 会说「今天练胸」「今天练背」，**但说不全器械的名字**，看到「高位下拉」「蝴蝶机」会犹豫。
- **看过很多教程**（短视频、图文），每个说法都不一样，越看越乱。
- **没法严格吃**：不会称重、不会每餐算克数。但会**尽量点健康一点的外卖**，会买蛋白粉补蛋白。
- 想要的不是「完美」，而是**有个人告诉我今天做什么，我做完就算数**。
- 怕的事：
  - 练错了、白练了；
  - 断了几天就觉得「我又放弃了」，然后干脆不练；
  - 被一堆专业名词吓住；
  - 被说教、被评判。

### 小周的语言

| 他会说 | 他不会说（或听不懂） |
|---|---|
| 今天练什么 | 训练单元、周期化 |
| 练胸 / 练背 / 练腿 | 离心、向心、RPE（除非解释过） |
| 做几组、每组几个 | 容量负荷、渐进超负荷 |
| 吃够蛋白 | 宏量营养素分配 |
| 好像没练到 | 目标肌群募集不足 |
| 断了几天 | 依从性 |

写作规则：**第一次出现的术语，必须用一句白话解释；解释不了就不用。**

### 他在哪里学东西（假设，需验证）
短视频平台、小红书、B 站、搜索引擎。**我们没有数据证明，写在这里是为了指导后续渠道验证。**

## 6. 信息屋（Message House）

```
                 ┌───────────────────────────────────────────┐
  屋顶（总信息）  │  不懂也能练对，不完美也能练下去。          │
                 └───────────────────────────────────────────┘
        ┌────────────────┬────────────────┬────────────────┬──────────────┐
 支柱   │ 1 不用想今天    │ 2 一组一组，    │ 3 吃得不完美，  │ 4 断了几天，  │
        │   练什么        │   看得懂        │   也心里有数    │   不算失败    │
        └────────────────┴────────────────┴────────────────┴──────────────┘
 地基   │  面向 18–30 岁、碎片时间、没有预算请私教的普通人；不做医疗判断      │
        └──────────────────────────────────────────────────────────────────┘
```

### 屋顶：总信息

**主句**：不懂也能练对，不完美也能练下去。
**备选**：
- 今天练什么，打开就知道。
- 不用懂，跟着做就行。
- 给没有教练的人，一份靠谱的今日清单。

> 屋顶要同时回答两件事：**我能不能做得对**（专业感）、**我做得不完美会不会被放弃**（陪伴感）。

### 支柱 1：不用想今天练什么

- **用户利益**：每天少一个决定。打开就是今天的部位、动作和组数。
- **他的画面**：站在器械前，不用发愣，看一眼清单就开练。
- **RTB（相信的理由）**

| 理由 | 状态 |
|---|---|
| 训练由「三分化 / 四分化」两套固定方法排出来，你选一套，之后按它轮转 | ✅ 代码已实现 |
| 轮转由「上一天练没练完」决定，不是由星期几决定 | ✅ 已实现（按完成情况推进，不依赖日期） |
| 每个动作有目标组数、次数 | ✅ 已实现 |
| 动作有示意动画 | ✅ 已实现（动作示意组件） |
| 有的动作暂时只用来「找重量」，会写明 | ✅ 已实现（校准期说明） |

### 支柱 2：一组一组，看得懂

- **用户利益**：每组都告诉你这组是干嘛的、做到什么程度算数，不用懂术语。
- **他的画面**：做第 4 组，屏幕上写着「最后一组，做到接近力竭」，他知道这组可以拼一点。
- **RTB**

| 理由 | 状态 |
|---|---|
| 每组标明类型（热身组、休息-暂停组等）和目标 | ✅ 已实现 |
| 做完一组由你点一下，记下次数和重量 | ✅ 已实现 |
| 练完有一段文字反馈：关键组做得怎么样、下次重点是什么 | ✅ 已实现（AI 文字，数字取自你的记录） |
| 有氧自由训练：跑步、骑行等，显示配速 | ✅ 已实现 |

### 支柱 3：吃得不完美，也心里有数

- **用户利益**：不用称重、不用算到克，也能知道今天蛋白够不够、还差多少。
- **他的画面**：吃完外卖，写一句「鸡腿饭」，晚上看到「蛋白还差一点，晚餐可以补」。
- **RTB**

| 理由 | 状态 |
|---|---|
| 记一餐，自动对应食物并估算热量和蛋白 | ✅ 已实现 |
| 食物库包含蛋白粉等常见补充 | ✅ 种子数据里有，**条目覆盖范围待核** |
| 餐后和每日反馈只讲「今天还差多少」，不判对错 | ✅ 已实现（prompt 规则） |
| 针对「外卖」的识别能力 | ❌ **未核实，不要宣称** |

### 支柱 4：断了几天，不算失败

- **用户利益**：休息、错过、延后都不会被记一笔，不会被催。
- **他的画面**：周三没去，周五打开，看到的是「今天接着练」，不是红色的「断签」。
- **RTB**

| 理由 | 状态 |
|---|---|
| 训练日轮转不按日历，没练完的那天还在原位 | ✅ 已实现 |
| 休息日 AI 不催你训练、不说「落后了」 | ✅ 已实现（prompt 规则） |
| 周目标可选，且文案不写「还差几次」 | ✅ 已实现（最近已改） |
| ⚠ 首页有「连续打卡」，**与这一支柱存在张力** | ⚠ **待 Sylvan 决定**：保留、改名，还是在休息日不计断 |
| 主观自评（睡眠、恢复）只做描述，不给「你该休息」的指令 | ✅ 已实现 |

### 地基：不做什么、给谁用

- 给谁：18–30 岁、碎片时间、没有预算请私教的普通人。
- 不做医疗判断，不诊断、不给治疗方案。
- 数据在你自己的账号下。**可导出、可删除**这一条，**要等删除功能配置并实测后才能对外说**。

## 7. 语言与语气

**一句话**：严肃但不板着，严谨但不吓人，有点幽默但不拿用户开玩笑。

### 规则

1. **价值在前，证据在后。** 一屏里先让他想象自己，再给一句证据。
2. **用他的词。** 第 2 节的「他会说」表是写作词典。
3. **术语第一次出现必须带一句白话。**
   例：「三分化：把全身分成三天，推、拉、腿，轮着练。」
4. **幽默来自场景，不来自产品装可爱。** 笑点是「你站在器械前发愣」，不是「我们的产品好害羞」。
5. **产品不是角色**，不写它的情绪、表情、动作（「它默默地……」）。猫只出现在视觉层。
6. **不吓人、不评判、不催。** 不说「你落后了」「别偷懒」。
7. **不承诺结果。** 不写「X 周瘦 X 斤」「保证增肌」。
8. **能量化就量化，但只用真实数字。** 不用编出来的百分比或用户数。
9. **严肃的事情严肃说**：医疗边界、数据与隐私、免责。这些地方不开玩笑。

### 同一件事，三种写法（示意）

| 事实 | ❌ 工程腔 | ❌ 过于卖萌 | ✅ 目标写法 |
|---|---|---|---|
| 训练按方法轮转 | 轮转由上一训练单元是否完成决定 | 今天轮到哪个小可爱啦～ | 今天练什么，打开就知道。没练完的那天，还在原地等你。 |
| 复盘 | 数字由程序计算，文字由 AI 整理，数字可追溯 | 小爪爪帮你复盘咯 | 练完一段话说清：哪几组做到了，下次重点是哪一组。 |
| 饮食 | 每餐热量和蛋白按公式估算 | 吃饱饱才有力气 | 不用称重。写一句今天吃了啥，晚上告诉你蛋白还差多少。 |
| 断练 | 不按日历排训练日 | 休息也是爱自己哦 | 周三没去？周五接着练。没有红字，没有「断签」。 |

### 幽默的位置（备选句，待选）
- 「今天练什么？别想了，打开就知道。」
- 「站在器械前发愣的时间，够做一组了。」
- 「做完一组，点一下。就一下。」
- 「看了一晚上教程，不如今晚开始练。」

## 8. 对官网和产品的含义

### 官网首页叙事顺序（建议）
1. **他的场景**：「是不是也这样：站在器械前不知道练什么」（S1）。
2. **屋顶一句话** + 主按钮。
3. **四根支柱**，各配一个手机画面（真实界面，演示数据）。
4. **一天怎么用**（早上看今天练什么 → 练 → 吃饭写一句 → 晚上一段话）。
5. **两种方法**，用白话讲，不堆术语。
6. **常见问题**（用他会问的话）。
7. **证据区（靠后）**：数据在你账号下、不做医疗判断、AI 会出错。

### 手机框里该演示哪几屏（按价值排序）
1. 今天练什么（支柱 1）
2. 一组的目标写得很清楚（支柱 2）
3. 吃了外卖，写一句（支柱 3）
4. 练完那段话（支柱 2）
5. 断了几天回来的样子（支柱 4）

### FAQ 要用他会问的话
- 「我不懂器械，能用吗？」
- 「没有健身房可以吗？」
- 「一天要花多久？」（**先不写具体分钟数，除非验证过**）
- 「断了几天还能接着练吗？」
- 「要称重吗？」
- 「它会让我怎么吃吗？」（不会替你做饮食处方）

## 9. 不能说的话（对外红线）

| 不能说 | 原因 |
|---|---|
| 能聊天、可以问它问题 | 当前不提供对话 |
| 连续打卡不断签 / 不记断签 | 首页有连续打卡 |

| 需要邀请码 | 代码里没有邀请码机制 |
| 连接 Oura、读取睡眠数据 | 尚未上线；上线后也只能展示，不宣传「AI 结合睡眠给建议」（Oura 协议限制） |

| 医疗、诊断、治疗相关表述 | 非医疗产品 |
| 用户数、评分、评价 | 没有真实数据 |
| 署名具体训练方法作者 | 官网不署名，仅写「基于公开的训练思路整理」 |
| 「按固定模板生成」「不是 AI 写的」 | 不实：复盘文字由 AI 生成 |

## 10. 待验证的假设与问题

**需要 Sylvan 决定**
1. 主攻细分人群是 A / B / C / D 哪一类？官网叙事跟着它走。
2. 首页「连续打卡」：保留、改名，还是休息日不计断？这直接决定支柱 4 能不能成立。
3. 目前两位内测用户各属于哪一类？

**需要用真实用户验证（建议与 2 位内测用户做 15 分钟聊天）**
1. 你在练的时候，最困扰你的瞬间是什么？
2. 上次想放弃是因为什么？
3. 你怎么描述今天练了什么给朋友听？（收集他的原话）
4. 你吃饭时怎么判断蛋白够不够？
5. 你看到「训练单元」「分化」这些词是什么感觉？
6. 如果官网只能写一句话，你觉得应该写什么？

**需要产品核实的事实**
1. 食物库对蛋白粉、外卖的覆盖到什么程度。
2. 「一天大概几分钟」的真实数据（先别写）。
3. 删除账号上线后，何时可以对外说「可导出、可删除」。
