# 小爪「记录 → 反馈 → 日终总结 → 校正」需求整理（草案）

来源：产品负责人口述（2026-10-23）。状态：需求草案，未实现的部分标注在「与现状的差距」。

## 想要的体验（原话整理）

1. **快速记录**：用一句话记运动、记吃饭。
2. **记完立刻有反馈**，且反馈针对"今天剩下的时间"：
   - 运动：今天练得够不够？够了就督促好好休息，给对应的休息、拉伸、放松建议。
   - 饮食：今天还应摄入多少热量、多少蛋白质。
3. **日终总结（wrap-up）**：一天的运动和饮食都记完后给一份简短总结，包含运动分析、饮食分析、两者综合分析。
4. **校正入口**：任何一条记录发现不对（例如奶茶加了黑糖珍珠，热量被估小了），可以从那条聊天卡片上直接点进去修改或校正。

## 与现状的差距

| 需求 | 现状 | 差距 |
|---|---|---|
| 1 快速记录 | 已有（文字；草稿 + 确认保存） | 无 |
| 2 饮食剩余热量/蛋白质 | 能查「今天还剩多少」，有营养待补条目时拒绝给数 | 记完后不会主动给；目标值来源需确认 |
| 2 运动够不够 + 休息建议 | 无 | 需定义「够了」的规则；建议是模型文字，不得带数字（现有规则） |
| 3 日终总结 | 无 | 触发时机、数据口径、文案边界都要定 |
| 4 校正入口 | 饮食卡保存后右下角「编辑 ›」跳饮食页编辑 | 运动卡、体重卡没有入口；「热量被估小」要能直接改热量，现在编辑动作只有改重量/换食物/删除/按比例 |

## 待决问题

- **目标值**：每日热量/蛋白质目标取自用户资料里哪个字段？没填时怎么办（建议：不给「还剩多少」，只说已吃多少）。
- **「练够了」**：按什么算？训练计划完成情况、当天运动分钟、还是用户自己说了算。建议先用「有今日训练计划且已完成」或「用户说练完了」，不用分钟数硬判。
- **日终总结触发**：用户说「今天记完了」/ 点一个按钮 / 晚上固定时间提醒。建议先做用户主动触发，不做推送。
- **总结里的数字**：全部由服务端从记录算出，模型只写不含数字的点评（沿用现有规则）；饮食有营养待补时明说不完整。
- **热量校正**：用户直接填「这杯实际约 X 千卡」。该条记为用户提供的固定值（不再标估算），且不进入食物库。
- **「一开始是语音」**：这句我没听懂是指语音先做，还是语音入口先做，请确认。
- 医疗边界：休息/拉伸建议只给通用常识，不诊断、不建议治疗。

## 建议的分期

1. 校正：运动卡/体重卡加「编辑」入口；饮食卡支持「改成 X 千卡」。
2. 记完即反馈：饮食剩余热量/蛋白质（有目标值时）；运动记完后的休息建议（通用，无数字）。
3. 日终总结：用户主动触发，服务端算数，模型写简短点评。
