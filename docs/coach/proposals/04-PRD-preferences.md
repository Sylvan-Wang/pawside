# PRD 04：偏好、忌口、过敏与记忆

状态：草案 · 依赖：ADR-008、Q16 · 对应 Patch §8、§9、B07 · **建议作为后续功能的第一步**（独立有用、风险低、是推荐的前置）

## 1. 目标
让小爪"记住我说过的事"（我不吃香菜），但**只记我明确说的**，我能看、能改、能删。
**非目标**：自动画像；从行为里猜病史；跨账号共享。

## 2. 三层模型（ADR-008）
| 层 | 例 | 写入条件 | 作用范围 | 可撤销 |
|---|---|---|---|---|
| 硬限制 | 过敏、长期不吃 | 用户**明确表达**（可聊天或设置页） | 所有推荐，**永不放宽** | ✓ 即时 |
| 软偏好 | 喜欢辣、做饭条件、爱吃牛肉 | 显式表达，或点赞/点踩的**有依据**推断 | 排序，可放宽 | ✓ |
| 本次条件 | 明天不吃鱼、只有15分钟 | 本句话 | **只此一次，不落库** | — |

## 3. 用户故事与验收
| ID | 故事 | 验收 |
|---|---|---|
| M1 | 我说"我不吃香菜" | 即时生效 + 告知"记下了：不吃香菜（长期）" + [撤销]；不需二次确认 |
| M2 | 我说"明天不吃鱼" | 仅本次推荐生效；**库里没有任何新行** |
| M3 | 我说"我对花生过敏" | 记为硬限制（过敏）；提示"配料不全时我无法保证避开" |
| M4 | 我想看小爪记住了什么 | 设置页列表：分层、来源（我说的/设置页）、时间；可编辑/删除/清空 |
| M5 | 我说"我有糖尿病" | **不默默写入长期记忆**；给出知情选择（要不要让小爪记住这类信息？）；默认不记；**不据此生成治疗菜单** |
| M6 | 我点了一次 👎 | 不产生永久食材禁令；仅近期排除该菜、温和降权有依据的相近做法 |
| M7 | 偏好冲突（喜欢辣 vs 过敏某辣料） | 硬限制优先，说明原因 |
| M8 | 删除账号 | 偏好全部删除（登记到 `USER_DATA_TABLES`） |

## 4. 功能需求
| ID | 需求 |
|---|---|
| R1 | 模型只**提出**偏好变更（结构化任务 `update_preference`：范围/期限/类型/原话摘要）；服务端校验后写入。**模型不能写"病史"类别** |
| R2 | 硬限制例外于"先确认再写"：即时生效 + 明确告知 + 一键撤销（Patch §3：长期明确不吃可直接保存并告知）。其余偏好变更走常规草稿确认 |
| R3 | 存储：`coach_preferences`（见 `09`），`revoked_at` 软撤销便于审计；用户删除是硬删除 |
| R4 | 送模型的上下文**只带必要偏好摘要**（Patch §9），不带全量历史 |
| R5 | 偏好变更来源字段：`explicit | settings | feedback`；`feedback` 来源默认不能成为硬限制 |
| R6 | 设置页入口：设置 → 小爪记住的 |
| R7 | 日志：偏好变更事件只记 id/类别，不记原话 |

## 5. 需要新增的规则与提示词改动（与现有闭环的衔接）
- `schemas.ts`：新增任务类型 `update_preference` 与 `scope: long_term|this_time`。
- 提示词（`PLAN_PROMPT_VERSION` 升版）：区分"不爱吃（长期）""这次不吃""过敏""医疗"；**医疗信息一律走 out_of_scope/知情选择，不写偏好**。
- 评测语料新增：长期不吃、本次不吃、过敏、病史、冲突偏好、否定句（"我不是不吃辣"）。
- 服务端：写入前再次校验类别白名单；`this_time` 永不落库（单元测试）。

## 6. 隐私与合规
- 健康相关信息（过敏属于健康信息）按敏感数据对待（PIPL/GDPR 视你的用户所在地，**需你判断**）。
- 隐私页新增"小爪记住的偏好"一段；用户可查看/更正/删除。
- 不与第三方共享；发给模型的只有当次需要的摘要。

## 7. 风险
| 风险 | 缓解 |
|---|---|
| 模型把一次性说法写成长期 | `scope` 由模型给；用评测语料覆盖（「明天不吃鱼」「这次不要香菜」）；写入后**立即告知并可一键撤销**，让错误可见且代价低。不做关键词兜底（容易误伤） |
| 把病史写进记忆 | 类别白名单 + 知情选择；评测用例 |
| 过敏被当作"口味" | 过敏单独类别；推荐时强规则 |
| 用户误以为"保证安全" | 所有相关文案写"无法保证"；配料不全不推荐 |

## 8. 测试映射
B07、B12（边界）、F29/B11（隔离与删除）；新增：属性测试——"任何推荐结果都不包含硬限制命中的项"。

## 9. 粗估
3–5 人天 + 设置页 1–2 人天（猜测）。
## 10. 需要你决定
存哪（新表 vs 档案字段，我建议新表）；病史信息的知情选择文案与默认值；硬限制是否需要"二次确认过敏"这类更严格流程；设置页入口位置。
