# PRD 02：产品内语音输入

状态：草案 · 依赖：ADR-006、Q14 · 对应 Patch §7.2、F02、F30、B02

## 1. 目标
让"说一句"比"打字"更省事，尤其是做完训练、手上有汗、或在做饭时。
**验收的关键不是"能转写"，而是"转写错了不会静默落账"。**

## 2. 范围
含：点击录音/停止/取消、60 秒上限、上传转写、文字回填可编辑、权限与失败兜底、与照片同一次输入。
不含：连续免提对话、语音播报回复、唤醒词、说话人识别、长期保存音频。

## 3. 用户故事与验收
| ID | 故事 | 验收 |
|---|---|---|
| V1 | 我点🎤说"中午吃了一碗面" | 文字回填输入框，我点发送才进入聊天；转写不自动发送 |
| V2 | 转写错了我改一下 | 输入框可编辑；发送的是我改后的文字 |
| V3 | 我不想录了 | 取消后无请求、无残留 |
| V4 | 没给麦克风权限 | 明确提示 + 一句话怎么开 + 可直接打字；不白屏 |
| V5 | 没说话/太吵 | "没听到声音"，可重录，不产生空消息 |
| V6 | 录太长 | 60 秒自动停止并转写；提示"最长 60 秒" |
| V7 | 网络差 | 失败可重试，**不丢录音**（内存保留直到成功或用户放弃）；不伪装转写完成 |
| V8 | 照片＋语音 | 同一条消息：图片附件 + 转写文字，走一次聊天回合 |
| V9 | 语音纠正 | "不是鸡肉，是鱼"转写后同样走草稿编辑，不新增一餐 |

## 4. 功能需求
| ID | 需求 |
|---|---|
| R1 | `MediaRecorder` 录制；按浏览器选择可用 MIME（Chrome: webm/opus；iOS Safari: mp4/aac，A6），**特性检测，不凭 API 存在宣称可用** |
| R2 | 单段上限 60 秒（可配）；体积上限随之；超出由客户端截断 |
| R3 | `POST /api/coach/transcribe`：校验登录/功能位/类型/大小/频率；转写后**立即丢弃音频**（默认不保存，Patch §7.2）；返回文字 + `language` |
| R4 | 回填输入框；**从不**直接发起聊天回合 |
| R5 | 失败分类：权限拒绝、设备不可用、无声、超时、上传失败、转写服务不可用 → 各有文案（见 `09` §5） |
| R6 | 兜底：任何失败都提示可打字；系统键盘听写作为文案里的备选建议，**但不算本功能完成** |
| R7 | 隐私：音频只为转写；隐私页如实披露（发给转写服务、不保存、处理后删除） |
| R8 | 观测：时长、转写耗时、失败类别；**不记录音频与文字原文** |

## 5. 方案要点（ADR-006）
- 为什么不用 Web Speech API：iOS 的 PWA 场景不稳（推测，需真机确认）。
- 转写服务：OpenAI 音频转写是候选（A2，**未验证**）；也可选其他，但"不隐式换成未知服务商"（Patch §2）。
- 成本/限额：每用户每日转写次数/总时长上限（起步建议 30 次，待定）。

## 6. 风险
| 风险 | 缓解 |
|---|---|
| iOS/Android 编码与权限差异 | 真机矩阵；特性检测；失败回退打字 |
| 方言/口音/食物名识别错 | 回填可改；真实样本测"转写后能否仍解析出正确食物" |
| 背景噪声导致乱码 | 无声/低质检测；不自动发送 |
| 隐私 | 默认不存音频；披露一致 |

## 7. 测试映射
F02、F30（无麦权限）、B02（真机）、V1–V9 的浏览器自动化（可用假转写接口覆盖状态机，**真机录音仍需手测**）。

## 8. 粗估与决定
粗估 4–6 人天 + 真机 2–3 人天（猜测）。需要你决定：转写服务；是否允许首版只做 Chrome/Android；60 秒是否合适；Q14。
