# PRD 05：小爪气泡与站内提示

状态：草案 · 依赖：PRD 03（食谱触发）、旧 Spec A7 · 对应 Patch §8（站内气泡）、旧 Spec D4/D5/D24

## 1. 目标
在**不打扰**的前提下，让用户知道"有一件对你有用的事"（周报好了、该选今天吃什么了）。克制比频繁更重要。
**非目标**：手机推送（Patch 明确不做）；基于猜测的罪恶感/医疗信息的主动提醒；每次都调用模型生成文案。

## 2. 规则（硬）
| # | 规则 | 来源 |
|---|---|---|
| N1 | **每天最多 1 个气泡**，按用户当地日期计 | 旧 Spec A7 / Patch |
| N2 | 可点 ✕ 关闭；关闭状态**跨会话**记住（服务端，不用 localStorage） | Patch |
| N3 | 文案是**固定模板**，不调用模型 | 旧 Spec A7 |
| N4 | 训练执行页隐藏；系统"减少动态效果"时无动画 | 旧 Spec A7 |
| N5 | 点气泡跳到对应内容 | 旧 Spec |
| N6 | 不基于猜测的情绪/医疗信息触发 | Patch §8 |
| N7 | 不额外调用 LLM | Patch B10 |

## 3. 触发（逐条核对，不擅自扩大）
| 触发 | 来源 | 文案模板（固定） | 前置 |
|---|---|---|---|
| 周报生成 | 旧 Spec D5/D24 | "hi，你的周报好啦" | 周报功能在线 |
| 双周身体变化生成 | 旧 Spec D5 | （模板待定） | **阶段 B 之后才有** |
| 有待确认的调整卡 | 旧 Spec D5 | （模板待定） | **阶段 C 之后才有** |
| **新增**：用户主动打开小爪后"今天还没想好吃什么？" | **本 Patch 增量**（食谱） | "今天还没想好吃什么？" | PRD 03 完成 |

> 旧 Spec 的三类触发**逐条核对**：目前代码里只有周报功能线（`/api/ai/compose` 的 weekly），双周与调整卡依赖未做的阶段。所以**今天真正能触发的只有"周报"**。新增的食谱触发要等 PRD 03。

## 4. 优先级与冲突
同一天多个触发符合时的顺序（建议）：待确认的调整卡 > 周报 > 食谱。只展示一个，其余**顺延到明天，不累积**。

## 5. 数据（`09`）
`coach_nudges(user_id, kind, ref_id, local_date, shown_at, dismissed_at)`；`unique (user_id, local_date)` 保证"每天一个"在数据库层成立。
- 展示：客户端 `GET /api/coach/nudge`；服务端判定今天是否已展示/已关闭，返回 0 或 1 个。
- 关闭：`POST .../dismiss`。
- 不展示时返回空，客户端不渲染任何东西。

## 6. 界面
见 `08` §5。位置：悬浮猫旁；不遮挡主要操作；点击气泡打开面板并滚动/跳转到对应内容。

## 7. 验收
| ID | 验收 |
|---|---|
| G1 | 同一天触发两次只出现 1 个气泡（数据库约束 + 测试） |
| G2 | 关闭后刷新/换设备/次日前都不再出现 |
| G3 | 训练执行页无气泡 |
| G4 | 气泡展示与点击不产生模型调用（日志里无 `coach_chat` 生成记录） |
| G5 | 减少动态效果开启时无动画 |
| G6 | 点击跳转到正确内容；内容不存在时降级为只打开面板 |

## 8. 风险
| 风险 | 缓解 |
|---|---|
| 变成打扰 | N1 数据库约束；先只开周报一种；观察关闭率 |
| 内容已失效（周报被删） | 点击时校验 `ref_id`，失效则降级 |
| 跨时区"今天"错位 | 以**用户当地日期**计（沿用服务端时区逻辑）；时区不明则不展示 |

## 9. 指标
`nudge_shown{kind}`、`nudge_dismissed{kind}`、点击率、关闭率。关闭率高 → 先降频而不是改文案。

## 10. 粗估与决定
粗估 2–3 人天（猜测；不含周报本身）。需要你决定：双周/调整卡模板；优先级顺序；是否允许用户在设置里完全关闭气泡（建议要）。Q17。
