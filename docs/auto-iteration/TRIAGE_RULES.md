# 分诊规则（防止临时 idea 变 P0）

每日例程排优先级时必须按这份规则来。规则本身只能在周末复盘后、通过 PR 修改。

## 1. 所有新东西先进「待评估」

来源包括：外部信号、xxa 或 Sylvan 的临时想法、用户反馈、例程自己发现的问题。新建一条 `backlog` + `待评估` 的 issue，写清楚：

- 一句话：要解决谁的什么问题
- 来源：链接或原话（外部信号至少 2 条证据，否则标「需要更多证据」）
- 服务哪个目标：增长（注册 / DAU）、付费验证、出海、留存、风险
- 粗估工作量：S（半天内）、M（1–3 天）、L（超过 3 天）

**当天提出的想法当天不开工。** 最快是下一轮例程评估后排期。

## 2. 优先级定义

| 级别 | 必须同时满足 | 一次最多几条 |
|---|---|---|
| P0 | ① 正在挡住 1000 用户 / DAU 100 目标，或是线上故障、安全、隐私、伤病风险；② 有证据（数据、≥2 条外部信号、或可复现的问题）；③ 本周能做完 | 2 |
| P1 | 满足 ① 和 ②，但本周做不完；或满足 ① 和 ③ 但证据不足 | 5 |
| P2 | 对目标有帮助，但不紧急 | 不限 |
| P3 | 想法好但现在不做；三个月后复查 | 不限 |

不满足 P0 的三条，最多排 P1。线上故障、数据泄露、可能伤人的建议，无论来源都直接 P0。

## 3. 人怎么改优先级

- 在周计划 issue 里回复「升到 P0」：例程会照做，但必须在 issue 里写明它不满足哪一条，并把这条记进周复盘。
- 一周内被人工破格升 P0 的超过 2 条，周复盘里单独讨论。
- 人可以随时把任何事降级或关掉，不需要理由。

## 4. 评分（给 P1–P3 内部排序）

沿用信号包的打分：`机会分 = 频次 + 情绪强度 + 战略相关 + 可执行 + 新颖`（各 1–5），`风险分 = 频次 + 情绪强度 + 战略相关 + 风险等级`。同级里分高的排前面。战略相关的打分参照第 5 节的当前重点。

## 5. 当前重点（周复盘时更新）

1. 增长：拿到前 100 个真实用户（含英文用户）
2. 出海：英文本地化（界面、方法文案、单位、官网英文版）
3. 付费验证：找到愿意付钱的信号（预售、付费意向、额度兑换）
4. 留存：新手第一周能练下去

## 6. 待批事项的选法（周五周计划第 1 节）

1. 只放需要人拍板的事：合并、上线、对外发布、定价、新 AI 用途、P0 破格、方向取舍、系统调整。系统自己能决定的不放。
2. 每条必须有：问题、2–4 个选项、推荐项和理由、不决定会怎样。
3. 排序：P0 相关 > 卡住下周任务的 > 其他。最多 10 条，不凑数。
4. 上周没批的事项合并成一条「仍在等」，不重复占位。
