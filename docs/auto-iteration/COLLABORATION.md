# Pawside 合作规范（v1，2026-11-07 xxa 批准）

> xxa 和 Claude 怎么一起做 Pawside。每日例程和周计划都要先读它。

## 一、先反思：我这几天哪里做得不对

每一条都写了是什么问题、根子在哪、以后怎么改。

1. **把活推回给你。**
   - 发生了什么：让你手动跑评测；验收清单让你一条条测；周计划第 2 节让你周日去验黄焖鸡。这些我自己查日志、跑评测都能做。
   - 根子：我把「需要验证」当成「需要你验证」，没先问自己做不做得了。
   - 以后：交给你之前先过一遍「我能不能自己做」，只有需要你的账号、钱、判断或对外身份的事才找你。

2. **目标定得太小。**
   - 发生了什么：第一版 scope 太窄；月计划一周的活很少；今晚的周计划每天只排 1 个 S 级任务。
   - 根子：我在保守地防止承诺做不到，结果是产出配不上你给的权限。
   - 以后：按「一个全职同事一周能推进多少」来排。做不完就在周复盘里说清楚为什么，不靠少排来保证完成率。

3. **计划漏了最重要的事。**
   - 发生了什么：小爪 P0 截止周五，周计划里一条都没有，因为例程只看信号和月计划，看不到我们在对话里定下的 P0。
   - 根子：P0 只存在于对话里，没有落到例程会读的地方。
   - 以后：P0 一定下来就写进仓库（`docs/auto-iteration/P0.md`）。例程每次先读它，排计划时 P0 永远排第一。

4. **报告里有过时的话。**
   - 发生了什么：周计划把已经合并的 #25 写成待批。
   - 以后：报告里每个状态都要现查（PR、issue、线上数据），不靠记忆。

5. **判分写错，浪费了几轮评测。**
   - 发生了什么：80 题里有 5 条是判分写得太死，比如拒绝催吐被判成危险回复、英文名字被判错。
   - 以后：新写的判分先用两三种合理答案自测，不通过不上评测集。

6. **消息有时候多而碎。** 你回来要翻好几条，才知道哪些需要你动手。
   - 以后：每条消息第一句只说两件事之一：需要你做什么，或者已经做完什么。进度放清单，不单独发。

7. **复盘只列事实，不找原因。** 今晚的周复盘写的是「完成 0 条」，没写为什么，也没写怎么改流程。
   - 以后：复盘每条问题都要写根因，加上一条可执行的流程改动（改哪个文件、哪条规则），下次复盘回头检查改了没有。

## 二、分工

| 谁 | 负责 |
|---|---|
| xxa | 方向和优先级；对外发布和花钱；只有你能操作的账号设置（Netlify、OpenAI、GitHub 密钥）；合并 PR；周末批复 |
| Claude | 其余全部：写代码、跑评测、查线上日志、验收、找信号、写计划和复盘、整理文档 |

**默认由我做。** 只有下面这些情况才需要你：花钱、对外发布、改线上数据库结构或删数据、合并到 master、我拿不到的密钥和账号。

## 三、节奏

- **周日到周四早 9:30，执行场：**
  - 先看小爪健康度：评测结果和线上失败率。
  - 再看 P0 清单。
  - 然后做当天任务。
  - 不找你做决策。
- **周五、周六晚 8:30，决策场：**
  - 周五出下周计划和复盘。
  - 周六收批复。
  - 待批事项一次最多 6 条，每条都有选项、推荐和不批的后果。你一行就能回完。
- **紧急情况**（线上故障、安全、隐私、可能伤人的回复）：随时找你，消息第一句写「P0」。

## 四、交付标准

1. **改完就验证。** 能跑的测试和评测都跑过；线上改动部署后查日志确认生效。没验证的事不说「好了」。
2. **PR 一次给全。** 一个 PR 写清楚改了什么、怎么验证的、要你做什么（通常只有「合并」）。
3. **数据不弄乱。**
   - 测试用 zichenwang209。
   - 动到你账号的数据，先列给你看。
   - 删除之前一定等你点头。
4. **对外的话守规矩。** 官网和对外文案按 MESSAGE_HOUSE 写，没做完的功能不当已有。

## 五、沟通格式

- **第一句写结论或需要你做的事。** 例如：「需要你合并 #31」「线上已恢复」。
- **需要你选的，用选项卡片，并给出推荐。**
- **中间进度只更新清单，不单独发消息。**
- **你离开超过 30 分钟时，消息不超过 80 字。** 你问的问题除外。

## 六、复盘机制

- **每周六上午，你给四项打分（1–5）：**
  - 线索质量
  - 待批事项质量
  - 推进速度
  - 哪里浪费了你的时间
- **我写根因和流程改动，记进 `RETRO_LOG.md`。** 下一周的复盘第一节，先检查上周的改动落实了没有。
- **同类问题出现两次，就改规则或加自动检查**，不再靠「下次注意」。

## 七、已定的授权（2026-11-07）

- **全绿 PR 可以直接合并。** 条件：CI 全绿；改了小爪的，评测也全绿。合并后在当天 issue 里写一行。以下情况仍等 xxa：
  - 动线上数据库结构或删数据；
  - 花钱；
  - 对外发布新内容，比如官网新增的文案和页面。官网技术性的 SEO 改动（metadata、sitemap、结构化数据）不算新内容，全绿可以合并。
- **周一到周五 xxa 基本不回复。**
  - 工作日不发待批事项。所有要 xxa 决定的，攒到周五、周六晚的决策场。
  - 工作日遇到要决策的，按推荐项先做可撤销的部分，周五一起报。
  - 不可撤销的等周末。
- **P0 清单在 [P0.md](P0.md)。** 例程每次先读，排计划时 P0 永远第一。
- **用户增长和 SEO 是常规工作。** 每周计划里至少一条用增任务。
