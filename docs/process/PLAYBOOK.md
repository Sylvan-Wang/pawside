# 从 0 到 1 的做法与工作流程（Sylvan × Claude）

内部文档，不对外。依据 2026-10-06 至 10-08 的实际工作提炼：官网、法务页、账号删除与导出、Oura 连接、修 CI。
**这是第一版草稿，由 Claude 根据对话整理，请 Sylvan 修改后再定稿。** 标「待确认」的是推断，不是原话。

## 一、核心原则

1. **先探索，再动手。** 新需求先说"先 explore"，看完选项、拍了板，才说"执行"。探索阶段不写代码。
2. **范围收窄，不被第三方绑架。** 只做眼前用得上的那一个（Oura 只给一个内测用户），结构留扩展口。"我们是独立的程序"，不依赖任何一家。
3. **能上线的只有真的做出来的。** 愿景可以讲，但必须带「规划中 / 内测中」角标；没有的功能不写成已有。
4. **合规是设计输入，不是上线前补的。** 条款和协议先读，再决定能做什么。Oura 协议禁止给 AI，结果是整个功能改成"只展示"。
5. **上线前必须过目。** 设计先对齐思路；页面本地看过；push 和部署前他点头。

## 二、一轮完整流程

```
触发（截图 / 用户反馈 / 想法）
  → 1. 探索：Claude 查文档、列选项、说清风险
  → 2. 拍板：Sylvan 定范围（做 / 不做 / 先做哪个）
  → 3. 分批排序：基础任务先做，风险高的单独列
  → 4. 合规：Claude 写事实说明（LEGAL_BRIEF），Sylvan 交给法务 agent，结论贴回
  → 5. 调研 / 参照：Sylvan 自己做市场调研、竞品拆解
  → 6. 实现：Claude 写代码、迁移、测试、文案
  → 7. 本地看：Sylvan 看效果，多轮纠偏（视觉、语气、定位）
  → 8. 推分支，CI 绿
  → 9. Sylvan 说"合" → 合并，Netlify 自动部署
  → 10. Sylvan 上线实测，反馈问题
  → 11. 沉淀：更新 STATUS、OURA_SETUP 等文档，保证下个会话能接手
```

## 三、分工

| Sylvan | Claude |
|---|---|
| 所有控制台操作：Oura 开发者后台、Netlify 环境变量、Supabase 迁移和开通功能 | 探索和方案 |
| 市场调研、竞品拆解、美术取向 | 代码、迁移、测试、文案 |
| 法务 agent 的往返（当传话人，并补事实） | 法务 brief、按结论改方案 |
| 最终拍板、"合"的指令、上线后实测 | CI 复现和修复、PR 管理、文档沉淀 |

交接方式：Sylvan 要**明确的、一步一步的任务**（"你给我要执行的任务明确一些，我现在去做"）。卡住就回贴截图或报错，Claude 改写步骤。看不懂就直说。

## 四、护栏（出事之后才立的规矩）

| 护栏 | 来自什么事 |
|---|---|
| `lib/site/features.ts` 登记每个功能的状态；`tests/site` 拦住不该出现的说法 | "每次有新功能，你都要记得同步官网" |
| 设备数据只展示、AI 相关文件不得引用；`tests/devices/no-ai.test.ts` 逐个扫描 | 法务发现 Oura 协议禁止数据给 AI |
| Oura 只申请 `daily`，令牌加密，断开立即删除 | 协议的数据保留和撤回要求 |
| 账号删除和完整导出 | 面向全球用户，隐私要求硬性 |
| 官网不提 Oura 和商业模式；市场话术只放内部 `MESSAGE_HOUSE.md` | 对外只写真实有的 |
| 联系邮箱统一一个 | 邮箱写错过 |
| 官网放在 `/welcome` 子路径，不动根域名 | 不想现在改 paw-side.com |

## 五、犯过的错 → 规则

| 错 | 规则 |
|---|---|
| 说"类型检查通过"，其实没装依赖 | **说完成之前必须真的跑过。** |
| 隐私政策和条款写了还不存在的功能（断开连接） | **条款只写已有的；功能做完再更新。** |
| 文案工程味重、讲内部机制 | **先立用户画像，再写；用用户价值说话，不用字段名和术语。** |
| 外包草稿的界面是臆想的，显得廉价 | **演示用真实界面和真实素材**（比如动作 GIF）。 |
| 内部说明文字被带到了线上页面 | **页面里不放写给自己看的话。** |
| 定位不准，说法在几套话语里飘 | **先定一句话定位，页面围着它。** 现在是"让你下一次打开时知道该从哪里继续"。 |
| CI 红了十几天没人追，根因是测试断言写错 | **红灯要追根，不能当背景噪音。** |
| 把别人的邮箱说成"不是你的" | **没核实的事不下判断，先问。** |

## 六、用到别的项目上，最小版本

1. 写一句话说清**给谁、解决什么、不做什么**。
2. 每个功能登记状态（已上线 / 内测中 / 规划中），对外话术只引用登记表。
3. 动手之前先读第三方协议，把"不能做什么"列出来。
4. 把每条"绝不能"变成**自动测试**，而不只是写在文档里。
5. 每个阶段末更新一份状态文档，写清：做了什么、没做什么、谁欠谁什么。
