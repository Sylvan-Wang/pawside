## 1. 结论

- 批 1 四个页面（连同它们直接用到的组件）里，去掉注释后**共 284 行**含写死的中文（共用组件只算一次；下表按页面列，合计 295）；另有 **80 行**在页面引用的 `lib/` 文案文件里（见第 3 节）。按每行平均 1–2 条字符串估，字典约 **350–450 条**。
- `CoachCard`（4 行，3 个页面用）和 `ExerciseMotion`（3 行，2 个页面用）是共用组件，翻一次全部生效。
- **最大的缺口不在代码里，在数据里**：动作名来自数据库 `exercises.canonical_name_zh`。线上 53 个动作，`canonical_name_en` **全部为空**（今天只读查询：53 / 0）。训练方法里的训练日名 `method_splits.name_zh` 同理。
- **单位基本不用动**：重量已有 kg / lb 切换（`lib/training-weight-unit.ts`，存库一律 kg）；饮食用 `kcal` 和 `g`，英文用户也认。只有日期格式写死了 `zh-CN`（`lib/utils.ts:133`）。
- **AI 生成的文字（每日 / 训练 / 饮食反馈、小爪回复）不在本批**：它们由模型用中文写，换语言要改提示词并跑评测，按硬规则另走待批。英文模式下这些卡片照常显示中文，PR 里写明。

## 5. 单位和日期

| 项 | 现状 | 英文模式下 |
|---|---|---|
| 重量 | 存 kg；逐组记录页已有 kg / lb 切换 | 不改存储；英文模式**不自动切 lb**，默认仍是 kg（周四任务的验收写的就是「kg 不变」），用户自己切 |
| 体重（首页小图） | 写死 `kg`（`app/home/page.tsx:657`、`664`） | 本批保持 kg；体重的 lb 显示进 backlog |
| 热量 / 蛋白质 | `kcal`、`g` | 不变 |
| 日期 | `lib/utils.ts:133` 写死 `zh-CN`；首页图表用 `MM-DD` 切片 | 跟随语言：`en-US` 显示 `Nov 16`；周一为一周开始不变（`getWeekStart`） |
| 星期、「本周 x/y 次」 | 字符串拼接 | 用带参数的字典条目，不拼接 |
