## 一句话

把"外部内容 → 训练方法"产品化：用户粘贴一段训练计划文字，系统在不让模型输出任何数字的前提下抽取成结构化草稿，用金标动作库补全并校验，用户几乎零摩擦地确认后，生成**私有方法**并训练。训练数据始终属于"用户 + 动作"，与方法脱钩，换方法、删方法都不会丢记录。

## 证据总表（详见 `99-final-rescan.md` 第 6 节）

| 项目 | 结果 |
|---|---|
| 本地环境 | PostgreSQL 16；master 的 27 个迁移从空库回放；叠加 5 份草案 |
| 对既有数据库的冲突 | `public` 表由 48 增至 58（正好 10 张新表）；写入训练历史后，应用草案前后事实表哈希逐表一致；哈希检查本身用两种故意违规验证过会报警 |
| 对既有合约的冲突 | 仓库自带 17 个合约：纯 master 与叠加全部草案结果完全一致（16 通过、1 个在两边都失败），草案没有破坏任何现有合约 |
| 新合约 | 4 份、106 条断言全部通过；14 次变异检验全部被抓到 |
| 规模 | 32 万行合成数据下，重度用户视图约 90 ms，专用查询约 8 ms，普通用户约 5 ms |
| 数量解析 | 对 22 条真实写法 22/22 |
| 动作库 | 文章里的 36 个动作都能在 302 条库里找到候选，多个有歧义，需标候选 |

**验证与复核中发现并已处理的问题**（共 10 项，详见 99 第 4 节；其中前 8 项已修入草案，另 2 项是更正我自己的原型预期、以及 Patch B 的遗漏与口径冲突）：删除报名会清空历史、激活后的 release 不可写入、保护触发器拦住账号删除、5 处检查约束阻止新分化键、内部函数对登录用户可执行、配额触发器泄露他人状态、客户端可自标"已发布"、错误的索引会变慢、数量解析的一处预期错误、Patch B 的遗漏与 B9 的口径冲突。**最终复扫另发现 4 处台账遗漏**（99 第 3 节）：进度接口读三个旧列、`SPLIT_LABELS` 回落原始键、日复盘在 Patch B 之后读报名表、新增的软删除读取方。
