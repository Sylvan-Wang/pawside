### 3.1 变异检验（证明合约会失败）
一份永远通过的合约没有价值，所以对 14 种典型破坏各跑了一次，全部被预期的断言抓到：

| 合约 | 破坏 | 被哪条抓到 |
|---|---|---|
| 数据脱钩 | 去掉防误删触发器 | M5：有历史的报名被删除 |
| 多日方法 | 去掉 M13 的级联放行 | 账号删除时被保护触发器拦住 |
| 多日方法 | 方法表读取策略改成人人可读 | M11：他人能看到私有方法 |
| 多日方法 | 内部辅助函数对登录用户可执行 | M10：内部函数权限 |
| 多日方法 | 轮转忽略"是否必需" | M7：可选的有氧日阻塞了一轮 |
| 多日方法 | 轮转不把"跳过"当作已解决 | M7：跳过的天未被视为已解决 |
| 导入与金标 | 配额触发器对他人写入也计数 | M15：泄露他人配额状态 |
| 导入与金标 | 插入策略允许 published | M15：客户端插入了已发布的导入 |
| 导入与金标 | 更新策略允许改为 published | M15：客户端把状态改成 published |
| 导入与金标 | 复用他人的草稿动作 | M16：复用了他人草稿 |
| 导入与金标 | 草稿上限改为 200 | M16：超过 100 个草稿 |
| 复盘与开关 | 复盘设置对所有人可读 | 他人能读到设置 |
| 复盘与开关 | 忽略白名单 | 白名单用户为关 |
| 复盘与开关 | 开关函数对匿名可执行 | 开关函数权限错误 |

### 3.2 合约在编写与验证中发现的问题（均已修入草案）
1. **配额触发器泄露他人状态**：触发器先于行级安全执行，用户 B 拿用户 A 的 ID 去插入，会收到"导入次数已达上限"，从而探测出 A 当天是否导过 5 次。已改为只对本人写入计数。
2. **内部辅助函数权限**：Supabase 默认给 `authenticated` 授予新函数的执行权限，只撤销 `public, anon` 不够。已对 `next_program_day`、`workout_log_type_for_split`、`enforce_import_quota`、`guard_enrollment_delete_with_history` 显式撤销。这是在把本地桩环境改得更贴近 Supabase 之后才暴露的。
3. 一处是测试自身的算术错误（草稿上限的循环次数差 1），不是草案缺陷。

## 8. 人工冒烟清单（对应发布阶段，文档 5 第 7 节）

**阶段 1（数据库先行）**
1. 在分支库跑 V1、V13，应用迁移，再跑一次，哈希一致。
2. 用现有测试账户登录：首页、训练、历史、周报、复盘全部与之前一样。
3. 对一个有历史的测试账户尝试删除其报名（SQL），被拒绝。

**阶段 2（运行时切换，白名单）**
1. 白名单账户完整走一轮 1.2：开始 → 记组 → 完成 → 下一天 → 整轮 → 第 2 轮。
2. 日志类型仍是 推/拉/腿，周报类型统计正常。
3. 非白名单账户行为完全不变。
4. 关掉开关后，白名单账户回到旧路径，数据不丢。

**阶段 3（导入，白名单）**
1. 粘贴肩部日一篇文章：摘要卡显示正确的天数与动作数；来源标签正确。
2. 粘贴一篇营养文章：提示"没找到训练计划"。
3. 勾选声明前按钮不可点；24 小时内第 6 次被拒绝并给出友好提示。
4. "全部接受建议"一次点击后可开始使用；动作对不上的默认保留我的写法。
5. 切换方法：旧方法归档，历史记录与同一动作的历史保留。
6. 另一个账户看不到我的私有方法。
7. 动作卡「⋯」：换一个、不做、调整组次、太难了、跳过这一天；"以后都这样"与"只这一次"行为不同；在「我的调整」里可撤销。
8. 不管怎么调整，开始训练、完成训练都能成功。

**阶段 4（复盘中心，白名单）**：用本文第 7 节表格里的场景，通过调整测试账户的记录日期造出各种状态逐一核对。
