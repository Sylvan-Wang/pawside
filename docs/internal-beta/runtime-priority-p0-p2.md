# Internal Beta Runtime P0–P2 排序决议

> 日期：2026-09-25  
> 方法：RICE 方向判断 + MoSCoW 交叉验证。当前没有用户规模和准确人天数据，因此不伪造数值型 RICE 分数。

| 优先级 | 需求 | MoSCoW | 排序依据 | 完成边界 |
| --- | --- | --- | --- | --- |
| P0 | Session 状态真实性、恢复、完成幂等与历史诊断 | Must | 错误推进会破坏训练序列和用户信任，且影响后续所有引擎的数据基础 | 查看不创建；开始不推进；未完成可恢复；完整完成只推进一次；历史仅诊断与单条受控修复 |
| P1 | 训练时长与当日体力适配 | Should | 两小时处方和 4/5 后力竭会直接阻断执行闭环 | Rules 生成执行版本；保留原始处方；记录预算、删减理由和版本；LLM 只解释 |
| P2 | lb/kg 快速输入与展示 | Should | 高频现场摩擦，范围较小且可独立验收 | 输入单位可切换；存储统一为 kg；保留换算精度与原始输入证据 |

## 实施顺序

严格按 P0 → P1 → P2 串行验收。P0 未通过前，不让时间适配或单位换算写入训练推进规则。
